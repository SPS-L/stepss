# Homebrew Tap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship STEPSS GUI on macOS through a Homebrew tap that updates itself on every release, document it, and pin it in the umbrella.

**Architecture:** A new public repository, `SPS-L/homebrew-stepss`, holds one cask and one workflow. The workflow is woken by the same `stepss-release` dispatch that `stepss-apt` and `stepss-scoop` already receive from java-ui's `promote` job, rewrites two lines of the cask, and proves the result on a macOS runner. Four repositories change, each pushed before the umbrella pins it.

**Tech Stack:** Homebrew cask DSL (Ruby), GitHub Actions, bash, Astro/Starlight MDX.

**Spec:** `docs/superpowers/specs/2026-10-13-homebrew-tap-design.md`

## Global Constraints

- Repository name is `SPS-L/homebrew-stepss`; the install command is `brew install --cask sps-l/stepss/stepss`.
- Cask dependencies are exactly `depends_on arch: :arm64` and `depends_on formula: ["openblas", "gcc"]`. No `depends_on macos`, no `--no-quarantine` anywhere.
- Asset name is `STEPSS-<version>.dmg` on tag `v<version>` of `SPS-L/stepss-java-ui`.
- Action versions: `actions/checkout@v7`. Major only.
- The built-in token is spelled `${{ github.token }}`. The only configured secret referenced anywhere is `STEPSS_TOKEN`, and only in stepss-java-ui.
- No `${{ }}` expression inside a `run:` script. Values arrive through `env:`.
- No em-dashes (U+2014) in any file. Markdown paragraphs are one line each, except in `installation.mdx` and `repositories.md`, which keep the wrapping they already have.
- The licence link is `https://stepss.sps-lab.org/getting-started/license/`. Never describe STEPSS as Apache 2.0 as a whole.
- Git: one command per invocation, never chained with `&&`, `||` or `;`. `cd` separately first.
- Commits carry `Petros Aristidou <apetros@pm.me>`. Check with `git log -1 --format='%an <%ae>'` after the first commit in each repository.
- `brew`, `gh`, `git push`, `codesign` and `npm install` need the Bash sandbox disabled on this Mac.

## Review Focus

1. **A Mac that already has a hand-installed `/Applications/STEPSS.app`.** `brew install --cask` refuses when the target exists. A reasonable user expects to be told what to do. Pinned in Task 1 Step 9 (observe the refusal) and documented in the README (Task 2) and the docs tab (Task 4).
2. **A release whose asset `digest` is null.** `jq` renders null as the string `null`, which is non-empty, so a naive check writes `sha256 "null"` into the cask. Expected: fall back to downloading and hashing. Pinned in Task 2 Step 2 (the `// ""` default and the 64-hex check) and Step 3 (local test of both).
3. **A three-component tag such as `v3.81.2`.** Expected: `version "3.81.2"` and a URL that resolves. Pinned in Task 2 Step 3.
4. **A Mac where `gcc` is missing or was uninstalled later.** The app opens and the first simulation fails. Expected: a check that names the missing library. Pinned by `tools/check-engine-libs.sh` in Task 1 and run in the `verify` job in Task 2.
5. **A tap Homebrew does not yet trust.** Expected: the documented command works as written on a machine that has never seen the tap. Pinned in Task 2 Step 8, whose observed output decides the wording in Task 4.

- [ ] **Step 3: Write the failing check, `tools/check-engine-libs.sh`**

```bash
#!/usr/bin/env bash
# Checks that every library the bundled macOS engines link against exists on
# this machine. The engines travel as .tar.gz resources inside stepss.jar and
# are extracted at run time, so neither jpackage nor Homebrew can see what they
# need: the cask's depends_on is written by hand, and this is what catches it
# going stale. A missing library otherwise shows up as an application that
# opens normally and fails on the first simulation.
set -euo pipefail

app="${1:-/Applications/STEPSS.app}"
jar="$app/Contents/app/stepss.jar"
if [ ! -f "$jar" ]; then
  echo "No stepss.jar under $app/Contents/app."
  exit 1
fi

work=$(mktemp -d)
trap 'rm -rf "$work"' EXIT

unzip -q "$jar" 'my/stepss/payload/*macos*.tar.gz' -d "$work"
for archive in "$work"/my/stepss/payload/*macos*.tar.gz; do
  dest="$work/$(basename "$archive" .tar.gz)"
  mkdir -p "$dest"
  tar -xzf "$archive" -C "$dest"
done

checked=0
missing=0
while IFS= read -r -d '' binary; do
  file -b "$binary" | grep -q 'Mach-O' || continue
  checked=$((checked + 1))
  while IFS= read -r lib; do
    # System libraries live in the dyld shared cache, not on disk.
    case "$lib" in /usr/lib/*|/System/*) continue ;; esac
    if [ -e "$lib" ]; then
      echo "ok       $(basename "$binary") -> $lib"
    else
      echo "MISSING  $(basename "$binary") -> $lib"
      missing=$((missing + 1))
    fi
  done < <(otool -L "$binary" | tail -n +2 | awk '{print $1}')
done < <(find "$work" -type f -not -name '*.tar.gz' -print0)

# A scan that finds nothing is not a pass: it means the payload moved.
if [ "$checked" -eq 0 ]; then
  echo "No Mach-O binary found in the macOS payloads of $jar."
  exit 1
fi
if [ "$missing" -ne 0 ]; then
  echo "$missing library reference(s) unresolved across $checked engine binaries."
  exit 1
fi
echo "All libraries resolve across $checked engine binaries."
```

Make it executable: `chmod +x tools/check-engine-libs.sh`.

- [ ] **Step 1: Write `README.md`**

````markdown
# STEPSS Homebrew tap

A [Homebrew](https://brew.sh/) tap for **STEPSS**, *Static and Transient Electric Power Systems Simulation*. It installs the desktop application on macOS and keeps it current, so a new release arrives through `brew upgrade` instead of being downloaded once per version.

```bash
brew install --cask sps-l/stepss/stepss
```

Thereafter:

```bash
brew upgrade --cask stepss
```

Uninstall with `brew uninstall --cask stepss`.

The cask brings Homebrew's `gcc` and `openblas` with it. That is the reason this route exists alongside the `.dmg`: the simulation engines load `libgfortran` and OpenBLAS from Homebrew at run time, and an application installed by hand opens normally and then fails on the first simulation unless both are already there.

If STEPSS is already in Applications from a `.dmg`, move it to the Trash first. Homebrew does not overwrite an application it did not install.

## What this route requires and what it is not

- **Apple Silicon.** There is no Intel macOS build of the engines.
- **The current release only.** The tap serves one version. To install a specific older build, take its `.dmg` from the [releases page](https://github.com/SPS-L/stepss-java-ui/releases).
- **A network connection on first launch.** The application is signed and notarized. The notarization ticket is stapled to the `.dmg`, not to the application inside it, so macOS verifies the installed copy with Apple the first time it opens.
- **This is not an official Homebrew cask**, and nothing in it has been through the Homebrew maintainers' review. Homebrew asks before loading a tap that is not its own; `brew trust --tap sps-l/stepss` records that once.

## Licensing

**STEPSS is not Apache 2.0 taken as a whole**, and the cask's caveat says so deliberately.

- **RAMSES**, the dynamic simulation engine, is the property of the University of Liège: proprietary, free for non-commercial use, capped at 1000 buses and 2 cores.
- **Helios** and **CODEGEN** are under Academic Public Licences.
- The two user interfaces, **stepss-java-ui** and **stepss-python-ui**, are Apache 2.0.

<https://stepss.sps-lab.org/getting-started/license/> is the single owner of these facts; everything here is a summary that points at it. Installing through Homebrew agrees to nothing, because the licence appears the first time you launch STEPSS. The `.dmg` is downloaded from the SPS-L release page and never mirrored here: the licence granted for RAMSES is non-transferable.

## How the cask stays current

`Casks/stepss.rb` is rewritten by `.github/workflows/update-cask.yml`, which is triggered four ways:

| Trigger | When |
|---|---|
| `repository_dispatch` (`stepss-release`) | stepss-java-ui fires it from the `promote` job of its release workflow, once the release is published with every platform attached |
| `schedule`, weekly | insurance, because a dropped or 401ing dispatch is silent on this side |
| `workflow_dispatch` | by hand |
| `push` to `main` | checks a hand edit; rewrites nothing |

It rewrites exactly two lines, `version` and `sha256`, and commits only if they moved. Everything else in the cask is hand-edited. The hash comes from the GitHub API's own per-asset digest. A `verify` job then installs the cask on a macOS runner and runs `tools/check-engine-libs.sh`, which fails when a bundled engine links a library the cask's dependencies do not provide.

### Two things that will break this quietly

- **The release asset name is a contract.** The cask resolves `STEPSS-<version>.dmg` on tag `v<version>` of stepss-java-ui. Renaming it there breaks every release cut afterwards, and older tags stay un-resyncable because the new name never existed on them. Rename it in both repositories in one pass or not at all.
- **A published asset must stay where it is.** Homebrew downloads an exact URL and verifies an exact digest, so deleting or re-uploading a release asset breaks every install of that version.

### Maintenance

| When | Do |
|---|---|
| Every release | Nothing. The dispatch updates the cask; check the `verify` job is green. |
| `.app` renamed, or the dmg layout changes | Edit `app` in the cask by hand; the workflow only touches `version` and `sha256`. |
| Engine linking changes | Adjust `depends_on formula:`. `tools/check-engine-libs.sh` names the library. |
| Red `verify` job | Read the failing step: `brew audit` names the stanza, the library check names the file. |
| Dropped dispatch | The Monday schedule catches it, or run `gh workflow run update-cask.yml`. |

### Troubleshooting

- `Error: Cask 'stepss' is unavailable`: use the full name `sps-l/stepss/stepss`, or run `brew tap sps-l/stepss` first.
- `It seems there is already an App at '/Applications/STEPSS.app'`: a copy installed from a `.dmg` is in the way. Move it to the Trash and install again.
- `dyld: Library not loaded: .../libgfortran.5.dylib`: `gcc` was removed after installing. Run `brew install gcc`.
- `"STEPSS" cannot be opened because the developer cannot be verified`: the Mac was offline at first launch. Connect and open it again.
- A checksum mismatch on install: the asset was re-uploaded after the cask was written. Run the update workflow.
````

- [ ] **Step 2: Write `.github/workflows/update-cask.yml`**

```yaml
name: Update the Homebrew cask

# Re-points Casks/stepss.rb at the newest stepss-java-ui release that carries a
# .dmg, and commits the result. A tap IS its git repository, so what is
# committed here is exactly what `brew upgrade` reads.
#
# Only two lines are ever rewritten: version and sha256. Everything else in the
# cask is hand-edited.
#
# No ${{ }} expression is interpolated into the text of a run: script. Values
# arrive through env: and are read as quoted shell variables, which is the
# convention across every stepss workflow and the reason a hostile release tag
# cannot reach this job's credentials.

on:
  # From the promote job of stepss-java-ui's release workflow, once the release
  # is published with every platform attached.
  repository_dispatch:
    types: [stepss-release]
  workflow_dispatch:
  push:
    branches: [main]
    paths:
      - 'Casks/**'
      - 'tools/**'
      - '.github/workflows/update-cask.yml'
  # Dispatches do not retry. A 401 or a dropped event otherwise means this tap
  # silently stops tracking releases. The run is idempotent, and commits
  # nothing when the cask already names the newest release.
  schedule:
    - cron: '41 4 * * 1'

concurrency:
  group: homebrew-cask
  cancel-in-progress: false

permissions:
  contents: read

env:
  UPSTREAM: SPS-L/stepss-java-ui
  SCAN_RELEASES: '5'
  CASK: Casks/stepss.rb

jobs:
  update:
    runs-on: ubuntu-latest
    permissions:
      contents: write
    steps:
      - uses: actions/checkout@v7

      - name: Find the newest release carrying a dmg
        id: find
        env:
          GH_TOKEN: ${{ github.token }}
          DISPATCHED_TAG: ${{ github.event.client_payload.tag }}
        run: |
          set -euo pipefail
          if [ -n "${DISPATCHED_TAG:-}" ]; then
            echo "Woken by $DISPATCHED_TAG."
          fi
          tags=$(gh release list --repo "$UPSTREAM" --limit "$SCAN_RELEASES" \
                   --exclude-drafts --exclude-pre-releases \
                   --json tagName --jq '.[].tagName')
          tag=""
          for candidate in $tags; do
            # `// ""`, because jq renders a null digest as the string "null",
            # which is not empty and would be written into the cask as a hash.
            line=$(gh api "repos/$UPSTREAM/releases/tags/$candidate" \
                     --jq '.assets[] | select(.name | endswith(".dmg"))
                           | "\(.name)\t\(.digest // "")\t\(.browser_download_url)"' \
                     | head -1 || true)
            if [ -n "$line" ]; then
              tag="$candidate"
              name=$(printf '%s' "$line" | cut -f1)
              digest=$(printf '%s' "$line" | cut -f2)
              url=$(printf '%s' "$line" | cut -f3)
              break
            fi
            echo "no dmg in $candidate"
          done
          if [ -z "$tag" ]; then
            echo "None of the last $SCAN_RELEASES releases carries a .dmg."
            exit 1
          fi
          hash="${digest#sha256:}"
          if [ -z "$hash" ]; then
            echo "The API reports no digest for $name; hashing the download."
            curl -fsSL -o asset.dmg "$url"
            hash=$(sha256sum asset.dmg | cut -d' ' -f1)
            rm -f asset.dmg
          fi
          version="${tag#v}"
          # Both values are about to be written into a Ruby file by sed.
          if ! printf '%s' "$hash" | grep -Eq '^[0-9a-f]{64}$'; then
            echo "Not a SHA-256: '$hash'."
            exit 1
          fi
          if ! printf '%s' "$version" | grep -Eq '^[0-9]+(\.[0-9]+)+$'; then
            echo "Not a version this cask can carry: '$version'."
            exit 1
          fi
          {
            echo "version=$version"
            echo "hash=$hash"
          } >> "$GITHUB_OUTPUT"
          echo "$name from $tag, sha256 $hash"

      # Skipped on push so the workflow cannot loop on a commit, its own or a
      # hand edit: a push only ever verifies what was pushed.
      - name: Rewrite the cask
        id: rewrite
        if: github.event_name != 'push'
        env:
          VERSION: ${{ steps.find.outputs.version }}
          HASH: ${{ steps.find.outputs.hash }}
        run: |
          set -euo pipefail
          sed -i -E "s|^  version \".*\"|  version \"$VERSION\"|" "$CASK"
          sed -i -E "s|^  sha256 \".*\"|  sha256 \"$HASH\"|" "$CASK"
          grep -q "^  version \"$VERSION\"" "$CASK"
          grep -q "^  sha256 \"$HASH\"" "$CASK"
          if git diff --quiet -- "$CASK"; then
            echo "changed=false" >> "$GITHUB_OUTPUT"
            echo "Already at $VERSION."
          else
            echo "changed=true" >> "$GITHUB_OUTPUT"
            git --no-pager diff -- "$CASK"
          fi

      - name: Commit it
        if: steps.rewrite.outputs.changed == 'true'
        env:
          VERSION: ${{ steps.find.outputs.version }}
        run: |
          set -euo pipefail
          git config user.name 'github-actions[bot]'
          git config user.email '41898282+github-actions[bot]@users.noreply.github.com'
          git add "$CASK"
          git commit -m "stepss: $VERSION"
          git push

  # On macOS after every run, so a renamed .app, a broken dmg or an engine that
  # started linking a library the cask does not provide fails here rather than
  # on every user's machine.
  verify:
    needs: update
    runs-on: macos-latest
    env:
      HOMEBREW_NO_AUTO_UPDATE: '1'
      HOMEBREW_NO_INSTALL_CLEANUP: '1'
    steps:
      - uses: actions/checkout@v7
        with:
          ref: main

      - name: Audit and install the cask
        run: |
          set -euo pipefail
          brew tap sps-l/stepss "$GITHUB_WORKSPACE"
          brew style sps-l/stepss
          brew audit --cask --online sps-l/stepss/stepss
          brew install --cask sps-l/stepss/stepss
          test -d /Applications/STEPSS.app

      - name: Check the engines find their libraries
        run: bash tools/check-engine-libs.sh /Applications/STEPSS.app

      - name: Uninstall
        run: brew uninstall --cask stepss
```

If Task 1 Step 6 showed Homebrew refusing an untrusted tap, add `brew trust --tap sps-l/stepss` as the line after `brew tap` in the "Audit and install the cask" step.
